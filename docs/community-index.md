# Community index

Status: proposed (ADR 002). Nothing publishes this index yet, and `mvmctl`
cannot read it yet.

Community packs are listed in `community/index.json`, separate from the
official `index.json`. An author contributes only a reference
(`community/publishers/<owner>.toml`); the author's own repository builds and
signs the pack. The registry signs nothing community.

## Layout

```
community/
├── publishers/<owner>.toml        reference, reviewed by pull request
├── index.json                     generated by the intake workflow
└── packs/<owner>/<name>/<version>/
    ├── manifest.json              verbatim copy of the author's signed manifest
    └── manifest.sigstore.json     verbatim copy of the author's bundle
```

`community/` is a registry root with the same layout as the official one, so a
client can point its `registry_url` at `.../main/community` and reuse its
fetch logic. The copies are small metadata files; application archives are
never copied and stay release assets of the author's repository.

## `index.json` (schema_version 3)

```json
{
  "schema_version": 3,
  "kind": "community",
  "packs": [
    {
      "namespace": "acme",
      "name": "tool",
      "description": "What the pack is for.",
      "publisher": {
        "repository": "acme/packs",
        "workflow": ".github/workflows/publish-pack.yml",
        "ref_pattern": "refs/tags/v*",
        "environment": ""
      },
      "versions": [
        {
          "version": "1.0.0",
          "manifest_sha256": "<64 lowercase hex over the exact manifest bytes>",
          "tags": ["latest"],
          "guest_arch": "aarch64",
          "size_bytes": 123
        }
      ]
    }
  ]
}
```

Versions use the same optional `tags`, `guest_arch` and `size_bytes` as the
official index extension (`mvm` contract `pack-registry-index-tags-platform`),
with the same rules: advisory only, a tag names at most one version, one
architecture per version. Unknown fields are refused. The `publisher` block is
copied from the reference file and must still equal it.

## Rules the validator enforces

- `schema_version` is `3` and `kind` is `community`. The official index is
  never `3`, so an old client rejects this file instead of misreading it.
- `namespace` is lowercase, not `mvm`, `agent` or `runtime`, and equals the
  owner of `publisher.repository`.
- `publisher` has exactly `repository`, `workflow`, `ref_pattern` and
  `environment`, and passes the same checks as a reference file.
- `manifest_sha256` is 64 lowercase hex; versions are unique; tags are unique
  across a pack's versions.
- Packs are sorted by `namespace/name`, versions newest first, so output is
  deterministic.

## What a client must do (proposal for the `mvm` owners)

1. Fetch `manifest.json` and `manifest.sigstore.json` from the community root
   and refuse unless the manifest bytes hash to the index pin.
2. Verify the bundle's certificate identity equals
   `https://github.com/<publisher.repository>/<publisher.workflow>@<ref>` with
   `<ref>` matching `publisher.ref_pattern` (and the environment, if set), under
   the GitHub Actions issuer.
3. Refuse unless the signer's repository owner equals the pack namespace.
4. Treat the index publisher block as discovery only: install only if the user
   has trusted that identity, either with an explicit `--trust-publisher` on
   first pull or a trust policy entry. Then pin it in a lockfile; a different
   signer for the same pack is an error.
5. Never grant a community namespace the built-in trust of `agent/` or
   `runtime/`.

## Intake (next step, not built)

A registry workflow resolves each reference: it lists the author's tagged
releases, downloads each `manifest.json` and bundle, checks the identity and
validation above, reads an application archive back against its descriptor
before listing, copies the two small files verbatim, and regenerates
`community/index.json`. A failing version is skipped and reported, never
signed or repaired.
